Copy AI ID WebmateLog 미수집 원인 보고서

Lexical 입력 버그를 추적하기 위해 WebmateLog를 심었지만, 브라우저에서 실제 로그가 수집되지 않은 이유를 쉽게 설명한 문서입니다.

최종 판단
collector 문제가 아니라 브라우저/확장 프로그램 전송 경로 문제
조치 상태
background service worker relay 추가 완료

결론

WebmateLog가 동작하지 않은 가장 가능성 높은 이유는 content script가 직접 http://127.0.0.1:8765로 로그를 보내는 방식이 Chrome의 로컬 네트워크/CORS/Private Network Access 정책에 막혔기 때문입니다.

WebmateLog collector 자체는 정상입니다. shell에서 직접 POST한 probe 로그는 성공했습니다. 빌드된 dist에도 WebmateLog 코드가 들어 있었습니다. 따라서 문제 지점은 collector가 아니라 브라우저 안에서 collector까지 가는 전송 경로입니다.

이 문제를 피하기 위해, content script가 직접 collector로 보내지 않고 Chrome extension background service worker를 거쳐 보내는 relay 구조를 추가했습니다. 또한 hash route에 붙은 copyaiidWebmateLog=1도 읽을 수 있게 보완했습니다.

핵심 요약

  • collector는 정상: local WebmateLog 서버는 살아 있고, 직접 POST한 로그는 저장되었습니다.
  • 브라우저 로그는 0건: copy-ai-id.notebook / lexical-shadow-input 실제 로그는 들어오지 않았습니다.
  • 가장 의심되는 원인: content script에서 localhost로 직접 fetch하는 요청이 Chrome 정책에 막혔고, 기존 helper가 에러를 조용히 삼켰습니다.
  • 수정 방향: content script → background service worker → WebmateLog collector 순서로 보내는 relay를 추가했습니다.

1. 원래 기대했던 로그 흐름

원래는 사용자가 에디터에 타이핑하면 아래 흐름으로 로그가 저장되어야 했습니다.

단계 역할 상태
1 Lexical editor에서 keydown/input/change 발생 계측 코드 추가됨
2 WebmateLog helper가 payload 생성 dist에 포함 확인
3 브라우저가 127.0.0.1:8765로 POST 문제 가능성이 가장 큼
4 collector가 SQLite에 저장 정상

2. 확인된 증거

확인 항목 결과 의미
collector health ok: true WebmateLog 서버는 살아 있음
shell POST probe inserted: 1 collector 쓰기 가능
브라우저 notebook 로그 0건 브라우저에서 collector까지 도달하지 않음
dist 문자열 검색 포함됨 빌드 산출물에는 WebmateLog 코드가 있음
collector OPTIONS 응답 Private Network 허용 헤더 없음 Chrome에서 content script → localhost 요청이 막힐 수 있음

3. 쉽게 설명한 원인

WebmateLog collector는 집 안에 있는 우편함처럼 정상적으로 열려 있었습니다. 터미널에서 직접 편지를 넣어보니 잘 들어갔습니다.

그런데 Chrome 안의 content script는 웹페이지 안에서 실행되는 특수한 코드입니다. 이 코드가 로컬 주소인 127.0.0.1로 직접 편지를 보내려고 하면, Chrome이 보안상 막을 수 있습니다.

게다가 기존 WebmateLog helper는 실패 이유를 console에 드러내지 않고 조용히 무시했습니다. 그래서 겉으로는 아무 에러가 없어 보이지만, collector에는 로그가 0건인 상태가 된 것입니다.

4. 적용한 수정

content script가 collector로 직접 보내는 대신, Chrome extension의 background service worker를 중간 전달자로 사용하도록 바꿨습니다.

수정 후 로그 전송 경로
content script
  → chrome.runtime.sendMessage(...)
  → background service worker
  → fetch('http://127.0.0.1:8765/api/logs')
  → WebmateLog collector
파일 내용
src/background/index.ts WebmateLog relay용 service worker 추가
src/shared/webmatelog-relay.ts relay message 타입과 validator 추가
src/manifest.ts background service worker 등록, localhost host permission 명시
src/editor/debug/webmatelog.ts relay 우선 전송, direct fetch fallback, hash query param 지원

5. 검증 방법

  1. Chrome의 chrome://extensions에서 unpacked extension을 다시 reload합니다.
  2. 대상 페이지를 아래 query와 함께 다시 엽니다.
    ?copyaiid=active&copyaiidWebmateLog=1
  3. editor가 열리면, 타이핑 전에도 아래 mount 로그가 먼저 들어와야 정상입니다.
    • draft-persistence-read
    • editor-shadow-root-prepared
    • editor-react-root-rendered
  4. 로그 조회는 아래 명령으로 확인합니다.
    curl -s 'http://127.0.0.1:8765/api/logs?namespace=copy-ai-id.notebook&scenario=lexical-shadow-input&limit=100' | python3 -m json.tool
